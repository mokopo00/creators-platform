| D-003 | 2026-10-27 | フロントと API を 1 つの Worker（Workers Static Assets）で配信する。CLAUDE.md 5 の「Cloudflare Pages」は採用しない | 同一オリジンにすることで、SameSite=Lax Cookie・Origin 検証・CSP を単純かつ安全に保てる。Cloudflare は Pages の後継として Workers Static Assets を推奨している。Pages を併用すると CORS とクロスサイト Cookie の扱いが必要になり、攻撃面が増える |

| D-005 | 2026-10-27 | 単体テストは Node 組み込みの `node:sqlite` 上に D1 互換アダプタを作り、本物のマイグレーション SQL で実行する | `@cloudflare/vitest-pool-workers` は Vitest のメジャーバージョンとの互換性に追従が必要なため。FTS5 を含む SQLite の挙動はそのまま検証できる |
| D-006 | 2026-10-27 | セッション ID は 32 バイト乱数を KV に保存し、Cookie には `ID.HMAC署名` を `__Host-sid`（HttpOnly・Secure・SameSite=Lax）で保存する | CLAUDE.md 5「署名付きセッション（KV保存）」。`__Host-` 接頭辞でサブドメインからの上書きを防ぐ |
| D-007 | 2026-10-27 | ID トークンは署名検証ではなく、Google のトークンエンドポイントから TLS で直接受け取った上で `iss`・`aud`・`exp` を検証する | OIDC Core 3.1.3.7 で許容される方式。JWKS 取得とキャッシュの実装・障害点を減らせる。スコープは `openid profile` のみでメールアドレスは要求しない |
| D-008 | 2026-10-27 | モック認証は `ENVIRONMENT` が `development`/`test` かつ `MOCK_AUTH=true` の場合のみ有効。ステージング・本番では設定値にかかわらず 404 | SPEC Phase 2。設定ミスでステージングに残っても無効になるよう二重条件にした |
| D-009 | 2026-10-27 | 署名付きアップロード URL は R2 の S3 互換プリサイン URL ではなく、Worker 自身が HMAC 署名した URL（ユーザー・MIME・サイズ・期限に束縛）で受け付ける | R2 のプリサイン URL は S3 API の認証情報が必要になり、秘密情報が増える。また Worker を通すことでマジックバイト検証と EXIF 除去を保存前に強制できる |
| D-010 | 2026-10-27 | 画像は JPEG（APP1/APP13）・PNG（eXIf/tEXt/iTXt/zTXt）・WebP（EXIF/XMP）のメタデータを除去する。動画のメタデータは MVP では除去しない | Workers 上で動画を再エンコードする手段がないため。`docs/SECURITY.md` に残課題として記録 |
| D-011 | 2026-10-27 | 依頼フローは「リクエストページで依頼作成（遅延条件に同意）→ チャット → 依頼者が確定して前払い → 納品 → 双方承認 → 送金」とした | CLAUDE.md 3-3 の流れに沿いつつ、チャットでの要望入力を支払い前に行えるようにした |
